# 讨论：macOS 输入法自动回切 App

## 市面上有类似的吗？

有一些**沾边**的，但**没有完全匹配你需求的**：

| App | 它做什么 | 缺什么 |
|-----|---------|--------|
| **Input Source Pro** | 光标旁显示当前输入法图标 | 没有超时回切 |
| **ShowyEdge** | 屏幕顶部彩条指示输入法 | 没有超时回切 |
| **KeyboardHolder** | 按 App 记住输入法偏好 | 没有超时回切 |
| **SwitchKey** | 切换 App 时自动切输入法 | 没有超时回切 |
| **Kawa** | 快捷键切换指定输入法 | 没有超时回切 |
| **鼠须管 (Rime)** | 内置 vim_mode 可以回英文 | 只限 Rime 自身，非系统级 |

**结论：「超时无操作自动回切英文」这个核心功能，目前没人做。** 这是一个真实存在但被忽略的痛点。

## 你的思路我觉得很好，我帮你补充和追问几个点

### 一、"超时"的定义需要打磨

这是最核心的体验问题：

**Q1：什么算"没有操作"？**
- 只看键盘空闲？
- 还是键盘 + 鼠标都空闲？
- 比如我在用鼠标浏览网页、滚动页面，其实根本不需要输入法 → 应该回切
- 但如果我在用鼠标点选微信聊天窗口准备打字 → 不应该回切
- **我的建议**：默认只看键盘空闲，鼠标活动不重置计时器。提供选项让用户改。

**Q2：有未上屏的拼音时怎么办？**
- 比如我打了 `zhong` 还没选字，这时候被强制切英文会很恼人
- 这个必须检测，有候选框的时候不能切

**Q3：锁屏 / 睡眠唤醒后呢？**
- 这其实是一个很自然的「回英文」时机
- 很多人的痛点就是：打开电脑，第一件事敲密码或者命令，结果发现是中文
- **建议直接做：唤醒即英文**

**Q4：切换 App 时要不要重置计时器？**
- 比如从微信切到 Terminal，应该直接切英文？还是等超时？
- 这引出了 per-app 规则的需求

---

### 二、浮动指示器的设计取舍

**Q5：和系统菜单栏的输入法图标是什么关系？**
- 系统已经有一个了，你再加一个浮动的，用户会不会觉得重复？
- **差异化在哪**：你的更大、更醒目、可以放在视觉焦点附近、还能显示倒计时

**Q6：指示器要显示多少信息？**

三种思路：

```
极简：     ● （红/绿圆点，6px）
适中：     中 | EN （文字胶囊）  
丰富：     中文 · 42s （带倒计时）
```

我个人倾向**适中 + 最后 N 秒才显示倒计时**，平时太多信息会烦。

**Q7：可拖动是刚需吗？**
- 可拖动意味着需要响应鼠标事件，会不会干扰前台应用？
- 替代方案：设置里选位置（左上/右上/左下/右下/跟随光标）
- 或者：按住 Option 才能拖动，平时鼠标穿透

**Q8：要不要做"光标跟随"模式？**
- 像 Input Source Pro 那样，指示器跟着文字光标走
- 好处：永远在你视觉焦点旁边
- 坏处：需要 Accessibility 权限，实现复杂，可能闪烁

### 三、Per-App 规则（我强烈建议加上）

这会大幅提升实用性：

| 场景 | 期望行为 |
|------|---------|
| Terminal / iTerm2 | **永远英文**，根本不需要超时 |
| VS Code / Xcode | 超时 **30s**，写代码英文为主 |
| 微信 / 钉钉 | 超时 **120s**，聊天中文为主 |
| 浏览器 | 跟随默认 60s |
| Spotlight | 弹出时切英文 |

这个功能 KeyboardHolder / SwitchKey 已经验证了需求是真实的，你在它们基础上加了超时维度。

### 五、需要注意的坑

1. **权限问题**：macOS 越来越严格，监听键盘事件需要**辅助功能权限**，你的 App 引导流程要做好
2. **输入法兼容性**：搜狗、微信输入法、百度输入法的 InputSource ID 都不一样，需要做兼容测试
3. **性能**：常驻后台 + 每秒检测空闲时间，CPU 占用要控制好，别成为"电池杀手"
4. **Sonoma / Sequoia 的变化**：新系统对输入法 API 有改动，要测试兼容性
5. **和 Karabiner 的冲突**：很多中文用户同时用 Karabiner 改键，要确保不冲突

### 六、商业化思路

这个需求其实很垂直：**中文开发者 / 终端用户 / Vim 用户**。

- 免费 + 开源可以快速获取口碑（GitHub、V2EX、少数派）
- 或者：基础功能免费，per-app 规则 / 统计 / 自定义样式收费
- 取名建议要体现"自动回英文"：比如 **InputGuard**、**TypeBack**、**英归 (EnReturn)**

## 一、你的批注引发的新问题

### 关于「Per-App 自定义超时」

你说终端也会写中文，不要"永远英文"，这个改动很好。但引出一个新问题：

**Q9：Per-App 配置的交互怎么做？**

两种思路：

```
思路 A（被动）：设置界面手动添加 App，一个个配
  → 繁琐，用户懒得配

思路 B（主动）：当你切换到一个新 App 时，
  浮标上多一个小按钮「为此 App 设置超时」
  或者 右键浮标 → "设置当前 App 超时: [30s] [60s] [120s] [自定义]"
  → 零门槛，用到才配
```

我建议 **B 为主，A 为辅**。日常用右键浮标快速配，设置界面做全局管理。

**Q10：没有配置过的 App，用什么默认值？**
- 需要一个全局默认超时（比如 60s）
- 用户第一次打开 App 就能用，不需要任何配置

---

### 关于「回切到哪个英文」

**Q11：你的"默认英文"是哪个？**

macOS 上英文输入法其实有好几个：
```
com.apple.keylayout.ABC            ← 大多数人用这个
com.apple.keylayout.US             ← 旧版系统残留
com.apple.keylayout.British        ← 英式
com.apple.keylayout.Dvorak         ← 小众
```

- 不能硬编码 ABC，要让用户选「回切目标」
- 或者自动检测：系统里装了哪些英文输入法，选第一个
- **建议**：设置里一个下拉框「回切到：[ABC ▾]」，首次启动自动检测填入

---

### 关于「有未上屏拼音时不切」

**Q12：技术上怎么检测候选框？**

这是一个**技术风险点**，值得提前想清楚：

```
方案 A：通过 Accessibility API 检测候选窗口是否存在
  → 可行，但不同输入法的候选窗口类名不一样
  → 搜狗、微信输入法、原生拼音，都得适配

方案 B：监听 MarkedText（未确认文本）
  → 更优雅，但需要当前焦点应用支持 NSTextInput 协议
  → 有些 Electron 应用可能拿不到

方案 C：保守策略 —— 如果最后一次按键是字母键且间隔很短，推迟切换
  → 粗糙但通用
```

**我的建议**：A + C 兜底。先尝试检测候选窗口，检测不到就用时间间隔启发式判断。这个需要早期重点测试。

## 二、你可能没想到的场景

### 场景 1：用户被自动切换后立刻又要打中文

```
用户打了一句中文 → 60s 到了 → TypeBack 自动切英文
→ 用户：不对，我还要继续打中文！→ 手动切回来
→ 60s 又到了 → 又被切走了
→ 用户：烦死了 🤬
```

**解法：「反悔冷却期」**
- 如果用户被自动切英文后，**5 秒内又手动切回中文**
- 说明这次自动切换是「误判」
- 此时**临时延长超时时间**（比如翻倍到 120s）
- 或者弹一个浮标提示：「已延长本次超时至 120s」

这个小细节会极大提升用户好感。

---

### 场景 2：全屏应用 / 演示模式

```
用户在全屏看视频 / PPT 演示 / 分享屏幕
→ 浮标出现在屏幕上很尴尬
→ 自动切换输入法也可能打断演示
```

**Q13：全屏时怎么办？**
- 选项 A：全屏时自动隐藏浮标 + 暂停超时
- 选项 B：全屏时只隐藏浮标，超时继续
- 选项 C：用户自己配

---

### 场景 3：多显示器

**Q14：浮标出现在哪个屏幕？**
- 跟随鼠标所在屏幕？
- 固定在主屏幕？
- 每个屏幕一个？（感觉过了）

建议：**跟随鼠标所在屏幕，记住在每个屏幕上的位置**。

---

### 场景 4：多个中文输入法共存

很多用户同时装了：
```
原生拼音 + 微信输入法（备用）
或 搜狗 + 原生（防止搜狗崩溃）
```

**Q15：TypeBack 需要区分不同的中文输入法吗？**
- 对于超时回切来说：不需要，只要不是英文就倒计时
- 但浮标显示可能需要：显示「微信」还是「搜狗」还是统一显示「中」？
- **建议**：统一显示「中」就行，不去区分。简单即正义。
